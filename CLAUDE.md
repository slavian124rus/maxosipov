# CLAUDE.md — правила работы ИИ в проекте «Максим Осипов · МаксИИм»

Этот файл читается первым перед любой задачей. Он короткий и строгий.
Подробности — в двух документах-источниках правды:

- **ARCHITECTURE.md** — как устроена система: стек, модули, данные, алгоритмы, ИИ, безопасность, этапы.
- **DESIGN.md** — как продукт выглядит и ощущается: бренд, цвета, шрифты, экраны, фигура мышц, тексты.
- **docs/plans/** — пошаговые планы этапов. Порядок работы исполнителя и контрольные точки ревью — `docs/plans/README.md`.

Если задача противоречит этим документам — остановись и спроси владельца. Не «улучшай» архитектуру молча.

---

## 1. Что мы строим

Личный бренд тренера **Максима Осипова** (10+ лет стажа, зал «Колизей», ул. Говорова, Красноярск).

- `maxosipov.ru` — лендинг: кто такой Максим, что за приложение, «первый месяц бесплатно».
- `app.maxosipov.ru` — PWA для посетителей зала (ставится на телефон):
  видео упражнений на тренажёрах зала, 2D-фигура с подсвеченными рабочими мышцами,
  дневник тренировок, алгоритм прогрессии весов и **ИИ-помощник МаксИИм** (главная ставка продукта).
- Там же — **кабинет тренера** (полностью под телефон) и **админка владельца** с гибкими ролями.

Главный пользователь — посетитель Колизея. Доступ по подписке: пробный месяц включается сам при регистрации,
дальше подписку выдаёт/продлевает Максим вручную. Онлайн-оплата — следующий этап, не MVP.

## 2. Нерушимые правила

1. **Стек фиксирован** (см. ARCHITECTURE.md §3). Новую зависимость добавляй только если без неё нельзя,
   и объясни зачем в описании изменения.
2. **Модули не лезут друг в друга.** Каждый модуль в `src/modules/<name>/` отдаёт наружу только
   то, что экспортировано из его `index.ts`. Импорт внутренних файлов чужого модуля запрещён.
3. **ИИ никогда не пишет в данные напрямую.** МаксИИм создаёт только *предложения* (`proposal`)
   и *черновики*; применяет их человек кнопкой. Любой новый ИИ-инструмент подчиняется этому правилу.
4. **Веса рекомендует алгоритм, а не модель.** Модуль `progression` — детерминированный код с тестами.
   ИИ только объясняет его результат человеческим языком.
5. **МаксИИм предлагает упражнения только из каталога зала** (у каждого есть видео и мышцы).
6. **Ничего не удаляется насовсем** — программы и тренировки уходят в архив, история весов вечна.
   Единственное исключение — удаление аккаунта по требованию клиента (152-ФЗ), см. ARCHITECTURE.md §12.
7. **Каждое действие проверяет права** через `rbac.can(user, permission, scope)`. Никаких проверок
   вида `if (user.role === 'trainer')` в коде.
7a. **Доступ по подписке проверяется на каждой странице и в каждой серверной функции**, а не в layout
   (`requireClientPage`, `assertClientAccess` — ARCHITECTURE.md §8.4). Страницы не обращаются к БД напрямую.
8. **Персональные данные — только на российском сервере** (FirstVPS). Не отправляй ПДн во внешние
   сервисы, кроме ИИ-провайдера в объёме, описанном в ARCHITECTURE.md §9.4.
9. **Секреты — только в переменных окружения.** Никогда не коммить ключи, `.env` — в `.gitignore`.
10. **Бренд — это настройки, а не код.** Название, цвета, логотип, зал берутся из `gym`/`brand`-настроек,
    чтобы позже переключиться на «KOLIZEY TEAM × Максим» и добавить филиалы без переделок.
11. **Интерфейс — на русском, на «ты».** Код, имена переменных, таблиц и коммитов — на английском.
    Правила текстов — DESIGN.md §9.

## 3. Как работать над задачей

1. Прочитай нужные разделы ARCHITECTURE.md и DESIGN.md.
2. Для новой функции — сначала короткий дизайн/план и согласие владельца, потом код.
3. **Логика предметной области пишется через тесты** (сначала тест, потом код):
   `progression`, `access`, `rbac`, разбор голосового ввода, применение предложений ИИ.
4. UI проверяй на ширине 375 px (iPhone) в первую очередь — это основной экран и клиента, и Максима.
5. Если изменение меняет архитектуру, модель данных, права или дизайн-правила —
   **обнови ARCHITECTURE.md / DESIGN.md в том же изменении.** Документы всегда отражают реальность.

## 4. Команды (создаются на этапе 0, держи их актуальными)

```
pnpm dev            # локальная разработка (сайт + приложение)
pnpm worker         # фоновые задачи (видео, подписки, уведомления)
pnpm test           # unit-тесты (Vitest)
pnpm test:e2e       # e2e (Playwright, мобильный вьюпорт)
pnpm lint           # ESLint + проверка типов (tsc --noEmit)
pnpm build          # продакшн-сборка (ловит серверный код в клиентском бандле; lint и тесты этого не видят)
pnpm test:media     # видео-пайплайн на фикстурах (нужен ffmpeg с libvidstab и python с opencv)
pnpm db:generate    # сгенерировать миграцию Drizzle
pnpm db:migrate     # применить миграции
pnpm db:seed        # тестовые данные: зал, роли, мышцы, 5 упражнений, клиенты
```

## 5. Готово = 

- типы проходят, линтер чистый, тесты зелёные, `pnpm build` проходит;
- всё, что нельзя проверить тестами (видео, подсветка), запущено на реальном ролике, результат приложен к отчёту (кадры или вывод);
- новая логика покрыта тестами, UI проверен на 375 px в тёмной теме;
- права проверяются через `rbac`;
- работает без сети там, где это обещано (тренировка, видео в кэше);
- документы обновлены, если что-то в них поменялось.

## 6. Чего не делать

- Не генерировать видео упражнений нейросетью и не брать чужие ролики — только съёмка Максима (DESIGN.md §7).
- Не добавлять онлайн-оплату, других тренеров, филиалы и т. п. раньше их этапа (ARCHITECTURE.md §15).
- Не использовать Google Fonts/CDN в рантайме — шрифты и ассеты лежат у нас.
- Не показывать клиенту «×» в схемах подходов: «3 подхода · 10–12 раз».
- Не трогать исходники в папках `Видео для примера как заниматься/` и `ФОТО ЗАЛА/` — это сырьё, только чтение.
