# Планы реализации — как по ним работать

Эти планы выполняет ИИ-исполнитель (недорогая модель). После каждого этапа — ревью владельцем/старшей моделью.
Перед любым этапом исполнитель читает: `CLAUDE.md` → этот файл → план этапа → разделы `ARCHITECTURE.md` и `DESIGN.md`, на которые ссылается план.

## Жёсткие правила исполнителя

1. **Делай только то, что написано в задаче.** Нет в плане — не делай. Неясно — остановись и задай вопрос в отчёте, не придумывай.
2. **Никогда не выдумывай API библиотек.** Перед использованием библиотеки открой её README/типы в `node_modules/<pkg>`
   или официальную документацию. Если метод из плана не существует в установленной версии — остановись, опиши расхождение.
3. **Имена — ровно как в плане**: файлы, функции, таблицы, колонки, коды прав, тексты интерфейса. Блок **Interfaces** — это контракт.
4. **TDD там, где в задаче есть тест:** сначала тест → запустить → увидеть падение → код → тест зелёный.
5. **После каждой задачи:** `pnpm lint && pnpm test` зелёные → коммит с сообщением из плана. В конце этапа — ещё `pnpm build` и e2e на свежей базе (e2e меняют подписки, повторный прогон без пересоздания базы падает).
6. **Не меняй** `CLAUDE.md`, `ARCHITECTURE.md`, `DESIGN.md` и планы. Нашёл противоречие — опиши в отчёте.
7. **Не добавляй зависимости** сверх перечисленных в задаче. Нужна ещё одна — остановись и спроси.
8. **Секреты** — только в `.env` (не коммитится). В репозитории — `.env.example` с пустыми значениями.
9. Тексты интерфейса — на русском, на «ты», правила `DESIGN.md §9`. Никакого «×» в схемах подходов.
10. Если три попытки починить одну ошибку не помогли — остановись, приложи лог в отчёт.

## Как отмечать прогресс

- В плане этапа отмечай чекбоксы `- [x]` по мере выполнения (это единственное разрешённое изменение плана).
- Коммиты — маленькие, по одному на задачу, в формате `feat(<модуль>): …`, `test(...)`, `chore(...)`, `fix(...)`.

## Контрольная точка в конце этапа (обязательно)

Исполнитель останавливается и пишет файл `docs/reports/<этап>-report.md`:

```
# Отчёт: этап NN
## Сделано — по задачам, с хэшами коммитов
## Как проверить — команды и шаги руками (URL, логины тестовых пользователей)
## Результаты: pnpm lint / pnpm test / pnpm test:e2e / pnpm build — вывод последних строк
## Отклонения от плана — что и почему
## Вопросы и риски
## Версии установленных пакетов (из package.json)
```

Дальше — **ревью**. Следующий этап начинается только после ответа «этап принят».
