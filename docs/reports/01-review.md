## Найденные проблемы

### F1. Обход экрана «нет доступа» — КРИТИЧНО

**Где:** `src/app/(app)/app/(client)/layout.tsx`, `src/middleware.ts`.

**Проблемы (две независимые):**
1. **Охрана в layout не срабатывает при переходах внутри приложения.** В App Router общий layout не перерисовывается при клиентской навигации между его страницами. Клиент с истёкшей подпиской открывает `/progress` (разрешено) и нажимает «Упражнения» в нижнем меню — layout не выполняется заново, страница открывается. e2e этого не ловит: он открывает `/exercises` через `page.goto` (полная загрузка).
2. **Заголовок `x-pathname` можно подделать.** Middleware ставит его только при rewrite. Запрос на `app.maxosipov.ru/app/exercises` идёт без rewrite (префикс `/app` пропускается) — и тогда layout читает `x-pathname`, присланный самим клиентом (`x-pathname: /progress` → «разрешено»).

**Исправление:**
- Охрана — **на каждой странице**, а не в layout: `src/modules/access/guard.ts` → `requireClientPage(path: string, opts?: { readOnly?: boolean }): Promise<CurrentUser>` (внутри — `decideRoute` + `redirect`). Вызвать первой строкой в каждой `page.tsx` группы `(client)` с её собственным путём-константой (`requireClientPage('/exercises')`). Для `/progress`, `/profile` — `readOnly: true`.
- Layout больше ничего не проверяет (только рисует меню). `x-pathname` удалить из middleware и кода.
- То же правило для данных: каждая серверная функция/роут, отдающий платные данные (каталог, видео, тренировки, МаксИИм на следующих этапах), вызывает `assertClientAccess(user)` из `access` и бросает 403. Добавь это правило в `CLAUDE.md` (сделано ревьюером) и используй в этапах 2–4.
- В middleware: на хосте `app` путь, начинающийся с `/app`, отдавать как `/404` (как на сайте) — внутренние пути не должны открываться напрямую. Дополни тест `rewriteTarget`: `('app','/app/exercises') → '/404'`.

**Тесты:**
- e2e `paywall.spec.ts`: клиент 5 открывает `/progress`, **нажимает** «Упражнения» в нижнем меню → оказывается на `/paywall`.
- e2e: запрос `app.localhost:3000/app/exercises` с заголовком `x-pathname: /progress` → 404.
- unit `rewriteTarget` — новый кейс выше.

### F2. Перебор кода из СМС параллельными запросами — КРИТИЧНО

**Где:** `src/modules/auth/otp.ts` → `verifyOtp`.

**Проблема:** счётчик попыток читается, сравнивается и увеличивается отдельными запросами. 200 одновременных запросов с разными кодами все увидят `attempts = 0` и все будут проверены — лимит «5 попыток» не работает, 4-значный код (10 000 вариантов) подбирается за минуты. Та же гонка позволяет использовать один код дважды.

**Исправление:**
- Сначала атомарно «забрать попытку»: `UPDATE otp_codes SET attempts = attempts + 1 WHERE id = $1 AND attempts < 5 AND consumed_at IS NULL AND expires_at > now() RETURNING *`. Нет строки → `too_many_attempts` / `expired` (определи по последней записи).
- Сравнивать хэш через `crypto.timingSafeEqual`.
- Погашать атомарно: `UPDATE … SET consumed_at = now() WHERE id = $1 AND consumed_at IS NULL RETURNING id` — нет строки → `invalid`.
- Дневной потолок: не больше 10 неверных вводов на номер за 24 часа (сумма `attempts` по номеру) → `too_many_attempts` с текстом «Слишком много попыток. Попробуй завтра или войди через VK/Яндекс».

**Тесты:** 20 параллельных `verifyOtp` с неверными кодами → в БД `attempts = 5`, ровно 5 вернули `invalid`, остальные `too_many_attempts`; 2 параллельных `verifyOtp` с верным кодом → ровно один `ok:true`; 11-я неверная попытка за сутки (через 3 разных кода) → отказ.

### F3. Кабинет тренера показывает всех клиентов без учёта прав

**Где:** `src/app/(app)/app/trainer/subscriptions/page.tsx`.

**Проблема:** страница сама ходит в БД (`users`, `roles`, `subscription_events`) мимо модуля `access` и `rbac`: тренер с областью `own` или «Администратор зала» без `clients.view` увидит всех клиентов и всю историю. Плюс грузится **вся** таблица событий без лимита, клиенты ищутся по имени роли «Клиент».

**Исправление:** функция в модуле `access` — `listSubscriptionsForActor(actor, { query, filter }): Promise<SubscriptionListItem[]>` (фильтрация по области права `subscriptions.grant`: `all` — все клиенты зала, `own` — `trainer_id = actor.id`; клиенты — пользователи без административных прав, а не по имени роли: роль клиента храни флагом `roles.is_client boolean` — миграция + сид) и `listSubscriptionEvents(actor, userId, limit = 10)`. Страница вызывает только их.

**Тесты:** тренер с `own` видит только своих; история возвращает ≤ 10 записей конкретного клиента; актор без права → `ForbiddenError`.

### F4. Редиректы OAuth строятся от адреса запроса

**Где:** `src/app/api/auth/[provider]/callback/route.ts`, `start/route.ts`, `logout/route.ts`.

**Проблема:** `new URL('/login…', request.url)` за Caddy в standalone-режиме может дать `http://0.0.0.0:3000/...` или `http://` вместо `https://`. Локально не проявится, в продакшне — сломанный вход.
**Исправление:** все редиректы — от `env.APP_URL`. Ошибки `signInWithVerifiedPhone` (аккаунт привязан к другому номеру) ловить и вести на `/login?error=linked` с текстом ошибки, а не отдавать 500.
**Тест:** unit на хелпер `appRedirect(path)` → `https://app.maxosipov.ru/login` при `APP_URL=https://app.maxosipov.ru`.

### F5. Подписки: потеря дней и даты в прошлом

**Где:** `src/modules/access/service.ts`.

1. `grant` замороженному клиенту считает от «сейчас» — оставшиеся замороженные дни сгорают. Исправление: для `frozen` база = `ends_at + (now − frozen_at)` (как при разморозке), затем продление.
2. `grant({ untilDate })` принимает дату в прошлом. Исправление: `untilDate <= now` → ошибка «Дата должна быть в будущем».
3. `startTrialIfEligible` — гонка: проверка `trial_registry` и вставка разделены. Исправление: `INSERT … ON CONFLICT DO NOTHING RETURNING` в `trial_registry`, подписку создавать только если строка вставлена; обе вставки — в одной транзакции.
4. Изменение подписки и запись события — в одной транзакции (`db.transaction`) во всех функциях.
5. `assertGrant` сначала ищет пользователя — посторонний узнаёт «Пользователь не найден». Сначала `assertCan(actor, 'subscriptions.grant')` без цели, потом поиск, потом проверка с целью.

**Тесты:** заморожен 10 дней назад с остатком 20 дней → `grant(+1)` → конец = старый конец + 10 дней + 1 месяц; `untilDate` вчера → ошибка; два параллельных `startTrialIfEligible` для одного номера → одна подписка.
