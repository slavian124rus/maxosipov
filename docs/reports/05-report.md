## Как проверить руками

1. `pnpm db:seed`, `pnpm dev`, `pnpm worker` (напоминания и итоги).
2. Войти Максимом `+79990000002` (код `1111`) → «Сегодня»: лента секций; «Клиенты» → карточка клиента.
3. «Заметки» → текст + «Показать клиенту» → войти клиентом `+79990000011` → «Профиль» → «Заметки Максима».
4. «Программа» → перетащить упражнение, изменить схему → клиент на `/workout` видит новую схему; в истории — «Откатить».
5. «Ещё» → «МаксИИм»: памятка, лимит, цены; «Статистика» — расход.
6. Владелец `+79990000001` → «Ещё» → «Роли и права» / «Люди» / «Журнал».
7. Push: `pnpm tsx scripts/gen-vapid.ts`, вписать `VAPID_*` в `.env`, установить PWA на iPhone, «Включить» в профиле; `notify` воркера или жалоба клиента присылает уведомление.

## Отклонения от плана

- В `ProgramPatch` добавлена операция `set_note` (в плане пункт меню «Заметка», но операции в схеме не было). Остальные операции не менялись.
- `assignTemplate` копирует шаблон клиентам **последовательно**, каждый в своей транзакции (как `copyTemplateToClient`), а не одной общей. Частичная выдача возможна; ошибка возвращается в интерфейс.
- `subscribers` `notify` читает VAPID-ключи из `process.env` в момент отправки (не из снимка `env`), чтобы тесты и запуск без ключей работали без перезапуска.
- `getAiSpend`: сумма за месяц — из `ai_usage_daily` (как учитывает этап 4), разбивка по моделям — из `ai_messages` × цены `aiPrices`; при пустых ценах стоимость по модели = 0.
- Фото контактов хранится как `photoMediaId` в `settings.contacts`, `photoUrl` не пересчитывается.
- Кнопки подписки в карточке клиента переиспользуют действия экрана «Подписки» (этап 1).
- История тренировок в карточке — списком без перехода в детальный экран (детальный экран остался клиентским).
- e2e в dev: формы с серверными действиями нажимаются с повтором и проверкой по БД (React-гидратация в dev не мгновенная); тест ролей возвращает роль клиента 5 в `afterEach`.
