## Отклонения от плана — что и почему

1. **Справочник мышц вынесен в `src/shared/muscles.ts`.** Клиентские компоненты (фигура,
   каталог, карточка) импортировали `muscleName` из `@/modules/catalog`, и в клиентский бандл
   попадал весь модуль с БД (`net`/`tls` → «Module not found»). Теперь чистые данные и функции
   лежат в `shared`, а `modules/catalog/muscles.ts` их ре-экспортирует — публичный API модуля
   не изменился.
2. **`/api/media/auth` проверяет `..` до `new URL`.** `new URL('/media/../../etc/passwd')`
   схлопывает путь, и запрос получал 403 вместо 400 из Review Focus. Проверка идёт по сырому
   `X-Forwarded-Uri`; тест руками: `400`.
3. **`copy_headers X-Forwarded-Uri` из плана не нужен.** По документации Caddy 2 `forward_auth`
   сам отправляет `X-Forwarded-Uri`, а `copy_headers` копирует заголовки *ответа*. В Caddyfile
   оставлен только `uri /api/media/auth`.
4. **Базовый образ runner — `node:22-bookworm-slim`.** В alpine-сборке ffmpeg без libvidstab;
   Debian ставит `ffmpeg` с `--enable-libvidstab`. Проверить сборку образа локально не удалось
   (Docker перестал запускать контейнеры, см. риски) — это первое, что нужно проверить на сервере.
5. **Тестовые данные каталога лежат в `scripts/seed-catalog.ts`**, а логика — в `ensureCatalog`
   внутри `scripts/seed.ts`. Так файл сида остался читаемым; сид по-прежнему идемпотентен.
6. **Постеры сида — `.jpg`, а не `.webp`.** Готовых webp нет, а перекодировать нечем (ffmpeg
   недоступен). Пайплайн пишет `poster.webp` для новых роликов; сид использует исходные jpg.
7. **`cropX` из мастера сохраняется в `media.processing_options`** через
   `setProcessingOptions` — в плане это поле было, но путь сохранения не описан.
8. **`assertClientAccess` вызывается и на страницах каталога** (после `requireClientPage`) —
   двойная защита по правилу ARCHITECTURE §8.4: страница и данные.
9. **`test:media` вынесен в отдельный конфиг-набор** (`tests/integration`), основной
   `pnpm test` его не запускает: тест требует ffmpeg и python с opencv.
10. **`test:py` указывает на `/opt/mt/bin/pytest`** (как в плане) — это путь внутри образа.
    Локально я запускал `py -m pytest media-tools` после установки numpy/scipy.
11. **Сид мастер-теста создаёт упражнения с уникальным именем** (`Date.now()`), иначе повторный
    прогон e2e падал на strict mode (две одинаковые строки).
12. **`videoStatus` и `hasMuscles` добавлены в `ExerciseListItem`** — тренеру нужен статус
    обработки в списке; клиентские экраны эти поля игнорируют.

## Вопросы и риски

1. **Видео-пайплайн и подсветка не проверены на реальном ролике.** На машине исполнителя нет
   ffmpeg (в PATH), а `docker run` перестал запускать контейнеры (контейнер зависает в `Created`;
   `docker ps`, `docker compose up` при этом работают). MediaPipe под Python 3.13 не ставится.
   Проверено: чистая функция команд (13 тестов), геометрия профилей (5 pytest), API загрузки
   и подписи (18 тестов), сборка Dockerfile — не проверена.
   **Что сделать на сервере:** `docker compose build`, затем `pnpm test:media` внутри образа
   и загрузка реального ролика; сравнить `muscles.mp4` с эталоном `lat-pulldown-muscles.mp4`.
2. **Задача 6, шаг 3 не выполнен:** раскадровки `docs/reports/assets/02-overlay-*.jpg` не сняты
   по той же причине. Скрипты и профили готовы, но визуального подтверждения совпадения с
   прототипом нет.
3. **Задача 8, шаг 6 выполнен частично:** e2e проходит мастер и сохраняет черновик; публикация
   после обработки не проверяется, потому что обработка требует ffmpeg. Публикацию проверяют
   unit-тесты (`publishExercise`: видео `ready`, мышцы, шаги).
4. **Деплой не выполнялся** — нет SSH и продакшн-окружения. Шаги 9.1 и 9.2 плана не отмечены.
5. **`media.process` ставится в очередь из веб-процесса** (`src/shared/queue.ts`, ленивый
   pg-boss). В dev без запущенного `pnpm worker` задача просто ждёт в очереди — это ожидаемо.
6. **`MEDIA_URL_SIGNING_SECRET` теперь обязателен** — в `.env.example` он есть, но на сервере
   нужно сгенерировать (`openssl rand -hex 24`), иначе приложение не стартует.
7. **Черновики и архив:** `archiveExercise` ставит `archived_at` и `draft`; в каталоге такие
   упражнения не видны, в истории остаются — по правилу «ничего не удаляем».
8. **`getExercise` для тренера вызывается с `includeDrafts: true`**, но проверка прав лежит
   на уровне страницы (`requireUser` + `trainer/layout`). Если появятся другие точки вызова,
   нужно добавить `assertCan(actor, 'catalog.edit')`.
9. **Сидовые упражнения ссылаются на реальные файлы прототипа** — при первом `db:seed` они
   копируются в `MEDIA_ROOT`. Если `data/media` очистить, постеры и видео пропадут: сид
   не перезаписывает существующие записи.
